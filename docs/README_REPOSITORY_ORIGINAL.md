# TwinFed-MoE

**Digital-Twin-Guided Federated Mixture-of-Experts for Personalized Remaining Useful Life Prediction in Heterogeneous IIoT**

This repository is the coding skeleton for the conference-paper implementation.

## Core pipeline

```text
Sensor Window
    |
    +--> Digital Twin Encoder --------+
    |                                 |
    +--> Transformer Encoder ---------+--> Twin-Aware Router --> Top-k Experts
                                                      |
                                                      v
                                              Weighted Expert Fusion
                                                      |
                                              Personalized Adapter
                                                      |
                                                      v
                                                 RUL Prediction

Federated server:
- aggregates shared Transformer parameters
- performs expert-utilization-aware aggregation
- leaves client-specific adapters local
```

## Recommended first experiment

Start with:

- Dataset: NASA C-MAPSS FD004
- Clients: 10
- Transformer layers: 2
- `d_model`: 128
- Experts: 4
- Top-k routing: 2
- Local epochs: 2
- Communication rounds: 30
- Batch size: 64

The default config uses a synthetic dataset so the entire pipeline can be tested immediately.

## Interactive FedTwin-RUL dashboard

The dashboard is a real historical replay of NASA C-MAPSS FD004 test engines.
Its RUL predictions are generated by the final FedTwin-RUL checkpoint rather
than mocked in the browser. It includes:

- cycle-by-cycle predicted and NASA-reference RUL
- digital-twin health proxy, drift, operating regime and twin-state context
- standardized sensor traces from the model's 14-channel input
- the actual 10-client non-IID partition and final three-seed comparison results
- configurable GREEN / AMBER / RED commands for later ESP8266 and Arduino Uno integration

Start it from the repository root:

```powershell
.\scripts\start_dashboard.ps1
```

Then open `http://127.0.0.1:5173`. To regenerate the bundled replay JSON from
the checkpoint and source dataset first, use:

```powershell
.\scripts\start_dashboard.ps1 -RegenerateData
```

The hardware status currently shown is a software command preview. It does not
claim that an Arduino, ESP8266, LED or relay is physically connected.

```text

```

Expected filenames:

```text
train_FD001.txt
test_FD001.txt
RUL_FD001.txt
...
train_FD004.txt
test_FD004.txt
RUL_FD004.txt
```

Then preprocess:

```bash
python scripts/preprocess_cmapss.py --subset FD004
```

The preprocessing script is intentionally marked with TODO blocks where experiment-specific choices such as sensor selection, RUL clipping, normalization and client partitioning must be frozen for the paper.

## Important research rule

Do not add equations to the manuscript unless the corresponding mechanism exists in code. This repository is structured so every major mathematical term can map to an implementation module:

- `L_RUL` -> `training/losses.py`
- `L_DT` -> `models/digital_twin.py`
- `L_prox` -> `training/losses.py`
- `L_bal` -> `training/losses.py`
- `L_TGC` -> `training/losses.py`
- expert utilization -> `models/router.py`
- expert-wise aggregation -> `federated/aggregation.py`



## Paper-valid C-MAPSS pass

This version replaces the prototype preprocessing. It now:

- uses 14 informative C-MAPSS sensor channels
- fits normalization only on the training data
- creates a 5-D Digital Twin auxiliary state from observable operating/sensor data
- contains no RUL-derived Digital Twin input
- creates a separate NASA held-out test split
- keeps complete physical engines on one federated client
- splits client training/validation data by engine
- stores operating-regime IDs for heterogeneous client construction
- writes round-level federated validation metrics to CSV

After replacing the old project with this version, run:

```powershell
python scripts\preprocess_cmapss.py --subset FD004
python scripts\validate_cmapss.py --subset FD004
python scripts\run_federated.py --config configs\fd004.yaml
```

The old `data/processed/FD004.npz` is obsolete and must not be used for paper results.
